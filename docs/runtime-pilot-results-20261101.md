## 发现的问题与处理

1. 正式模组冷启动时，AE工程师升级注册经 `ModHelper.AddNetworkUpgrade` 提前触发惰性 `PlayerStore`，在开局数据未就绪时抛出空引用。0.9.2 将注册延后到真实新开局/读档生命周期，并使注册幂等，关闭时避免创建单例。
2. 新游戏已有真实主库存和开局回调，但 `GameSession.Loading` 始终为 true，阻止测试及正常网络操作。0.9.3 增加 `OnNewGameStarted` 的会话重置、主库存接入和当日初始化。后续两次八项通过均使用该正式版本。
3. 试验宿主也经历修订：移除未列出的 Core 静态引用，保留显式反射权限；提前摆完线缆避免普通测试物品占用预留位置；逐条序列化用例，解决动态模组中 Unity 遗漏嵌套列表的问题。这些是宿主或装配问题，未记为正式功能通过。

历史尝试保留在各自目录：12:52、13:04、13:07 的启动/就绪阻断未执行完整八项；13:10 在第三项被宿主摆放冲突阻断；13:13 首次完整通过；13:17 加入提示自动处理后完整复跑通过。早期缺失的结构化用例行没有补填 PASS。

## 存档与自动执行边界

每次 arm 都先备份已有主存档和索引，记录已有槽 ID，再创建专属场景；写入前核对新场景、新槽及同一会话身份。arm 在任何开局操作前改名领取，失败不自动重放，成功保存并正常退出游戏。本轮留下测试槽 4–9，未删除它们。

末次核对原有正常槽 0–3：文件长度和原记录精度内的修改时间均未变化，记录见 `original-save-metadata-check.json`；这不是内容哈希证明。最初的 PowerShell 日期比较因 JSON 毫秒精度/日期解析导致假阴性，已用原始 JSON 的 Unix 毫秒值重新核对。存档索引会因新增测试槽更新。

测试插件仍安装并启用，但末次 arm 已消费，当前不再自动运行。再次测试需先退出游戏，再执行 `scripts/runtime-pilot.ps1 -Launch`；普通启动不自动选档或写入。
