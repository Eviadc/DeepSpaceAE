# DeepSpaceAE 0.1.0-alpha · 游戏内测试

目标：Windows x64，游戏内 `100-REV3`，Steam Build `26284217`（版本标识由用户提供）。此包已用用户上传的该安装实例真实程序集编译；**云端未启动游戏，加载、UI、取放、保存/载入均等待本地实测**。这是早期测试包，不是稳定发布版。

## 安装与启用

1. 退出游戏，将 ZIP 中的整个 `DeepSpaceAE` 文件夹解压到游戏安装目录的 `Mods` 下面。不要再多套一层同名文件夹。
2. 确认 `Mods/DeepSpaceAE/manifest.xml`、`DeepSpaceAE.Core.dll`、`DeepSpaceAE.GameAdapter.dll` 同级，另有 `Textures/Items` 下四张 PNG。
3. 启动游戏，在模组菜单中启用 **DeepSpaceAE 测试版**，然后重启游戏。
4. 打开 F8，应看到 DeepSpaceAE 初始化、启用及注册四种部件的日志。如被拒绝，运行 `mod-scan deepspaceae`，保留原始错误日志反馈；不要通过更改能力声明或关闭扫描器掩盖问题。

Core 是依赖库，不含 IMod 入口；加载器若提示在 Core 中未找到入口并跳过入口实例化，是预期行为。判断本模组是否加载，应看随后 GameAdapter 的初始化日志与模组菜单状态。

没有额外模组前置，不需要自行安装 .NET SDK、Unity Editor 或替换游戏 DLL。本包仅列出两个自有程序集，清单能力为空，不包含游戏、Unity、Harmony 或 Steam DLL。

## 生成部件与放置网络

请使用**独立测试存档**。此构建会生成模组物品，且实验搬运可能触发原生/其他模组回调；尚未验证存档往返或故障恢复，不能保证现有进度安全。

1. 载入测试存档，在主物品栏留出至少 9 个空格。
2. 按 F9，在 **Spawn** 栏点击 **AE: Spawn kit**，生成核心×1、管线×6、存储总线×1、终端×1。放不下的新部件会被游戏的原生入口丢弃，不会为了生成部件删除已有物品；数量结果看 F8。
3. 将部件直接放在**主物品栏**，通过侧边接触连接。先按下面的最小结构摆放（多余管线可放远处）：

```text
核心 ─ 管线 ─ 终端
        │
       总线 ─ 真实容器
```

“真实容器”是本来就能存放物品的、归玩家拥有的箱子或背包等，放在主库存并与总线侧边接触；先放入一件普通测试物品。AE 总线不会创造虚拟仓库，也不会复制接入物品。

部件本身定义为 1×1，使用原创占位贴图。实际接触判定直接调用此版本的 `GameItem.IsAdjacent`，由游戏处理形状和旋转，不通过屏幕位置猜测。对角不作为我们额外添加的连接。

## 打开终端与读取

按 F9，在 **Special** 栏点击 **AE: Open terminal**；也可以使用游戏对终端物品提供的“激活”操作。若激活核心或总线，当前测试版也会打开主库存中的终端。

- 总线旁只有一个可识别容器时自动接入。若有多个，在终端窗口为该总线点击相应“接入”按钮选择；选择仅保留在本次游戏会话，重新载入后需重新确认。
- 只索引所选容器的**直接物品**，不递归暴露里面其他背包的物品。它自己的多个直接库存栏可一起观测。
- 默认频道开启：每个终端/总线各占 1，核心承载 32、每段管线承载 8。频道不足、无核心或同一连通网络多个核心会离线。终端和总线不充当管线；同时碰到两个独立传输网络时保持离线。
- 点击“刷新网络与容器”重新观测；当前不做每帧扫描或承诺实时自动刷新。每次实际搬运都会额外重读，不依据旧窗口内容直接写入。
- 同物品 ID 不同实例分开显示，不按状态推断可合并。每页显示 30 个实例，可翻页；短 ID 只用于本次会话中的显示，不是游戏持久 ID。

先只读检查：接入物品是否出现、断开管线后是否消失、重连后能否恢复、两件不同状态的同类物品是否保持独立。频道开关只改变本次会话策略，不写入独立持久配置。

## 实验取放（默认关闭）

仅在上述只读检查符合预期后，才在终端开启“实验取放（仅测试档；整实例、不堆叠）”。

- **取出**：点击接入实例的“取出整实例”，目标为主库存。
- **存入**：选择一个在线总线，再选择主库存里的物品。目标容器和 AE 部件本身不在该存入列表中，防止误把设备或已接入容器挪走。
- 不主动请求拆分、自动堆叠或批量搬运。若原生预检找到的位置会合并堆叠、部分接受或转入嵌套容器，本版拒绝该操作；即使别处可能还有空位，也不会强行绕过规则。原生回调仍可能改变最终行为，因此必须核查实际结果，不能把这些限制当成绝对安全保证。
- 移动前检查源实例/归属、有效拥有、移除/接收规则、位置、当前连通及频道；使用真实 `SlotMarker.TryAcceptOnce` 搬运并检查同一实例的数量与归属结果。不自行先删后造，不使用 `UncheckedAccept` 搬运已有物品。
- **这不是原子事务。** 原生入口会先逐出源，再接收入目标，中间可能有回调。异常或后置条件不一致时锁定本次会话写入，不自动重试、回滚、销毁或补造物品。请停止测试并保存 F8 日志；不要通过反复点击或重新载入来验证恢复。
- 并发、其他模组回调、写入后的异常与崩溃恢复尚未在真实游戏测试。开启实验选项不表示已证明安全。

## 反馈与卸载

请反馈：是否出现在模组菜单、F8 初始化/扫描错误、F9 按钮是否存在、部件与容器摆放截图、终端状态、复现步骤，以及本次实际通过/失败的检查。日志若包含本地用户名或路径，可自行遮盖。

退出前如要保留测试存档，请先从所有库存中移除**全部 AE 部件**，再按游戏流程保存；之后停用模组并重启。接入箱子的物品本身不是虚拟库存，不随总线持有。完整卸载/保存往返仍未验证，最稳妥的测试结束方式是弃用此独立测试档。

不需要发布到创意工坊。后续更新前退出游戏，替换模组文件；如提示审核并启用，按游戏提示处理。
