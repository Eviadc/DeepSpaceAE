# DeepSpaceAE 0.1.0-alpha · 游戏内测试

目标：Windows x64，游戏内 100-REV3，Steam Build 26284217（用户报告）。文件名的源码后缀区分每次实验构建。已用用户提供的真实程序集编译；**本次双击、3×3 核心、定向总线和连接贴图尚未在游戏内验证**。默认只读，实验取放必须手动开启，仅用于独立测试存档。

## 安装与工具

1. 退出游戏，将 ZIP 中整个 DeepSpaceAE 文件夹放到游戏安装目录的 Mods 下。manifest.xml 与两个自有 DLL 同级，Textures/Items 中应有 20 张自有 PNG。不要保留其他版本的额外 DLL。
2. 在游戏模组菜单启用 **DeepSpaceAE Test** 并重新启动。扫描被拒绝时保留错误，不修改能力声明或关闭扫描器来掩盖问题。
3. 使用 F8/F9 前，先退出游戏，在 Probably Stolen.exe 同级目录创建空文件 **dev.txt**，再启动游戏。Windows 请显示扩展名，避免 dev.txt.txt；不需要启动参数。模组详情的“开发者模式”是另一项信任设置。
4. F8 是控制台，F9 是开发菜单；有多媒体功能键时可尝试 Fn+F8/Fn+F9。本模组的日志和加载名称使用英文/ASCII，窗口说明仍可用中文。更新后先 Clear 一次旧日志；若仍有缺字警告，请保留新日志来源，不要全局屏蔽错误。

核心由旧版 1×1 改为 **3×3**。请用新独立测试档重新生成设备，避免把已有部件存档当作升级兼容性测试。旧 c5d6faa 包还存在错误根库存绑定，不能用于本轮复测。

## 生成、拖拽与双击

载入独立测试档，主物品栏留出一个连续 3×3 空间及至少 8 个其他空格。按 **F9 > Spawn > AE: Spawn kit**：核心×1、管线×6、物品存储总线×1、终端×1，共 9 个物品，占格合计 17。

结果窗口中的 main 是直接放进主库存的数量，nested 是被原生放置规则转入内部容器的数量，not kept 是未保留数；同时显示生成前后的部件计数。不要反复点击来判断有没有生成，每次都会请求新套件。放不下的新部件会由原生入口处理，不删除已有物品腾位置。

四类组件都只在**双击**时打开 AE 窗口。单击和拖拽保留原生搬运行为，不修改游戏的全局单击选项。核心、管线和总线打开部件说明窗口，终端打开物品目录；部件窗口也有打开终端和只读诊断按钮。F9 > Special > AE: Open terminal 是独立测试入口。

请先分别验证单击不弹窗、拖动可放置、双击只打开一次窗口。

## 连接与定向总线

组件直接放在**主物品栏**中。核心占 3×3，其他部件占 1×1。下图每个符号对应一格；C 是同一个核心的九格，- 是管线，T 是终端，> 是朝右的总线，B 表示真实容器的一格：

    C C C . . .
    C C C - T .
    C C C - > B

总线**箭头面是唯一容器接入面，背面是唯一网络连接面**。朝右时只识别右边紧邻格实际覆盖的容器，只从左面接核心或管线。其他两侧的容器与设备不提供接入。拖拽中使用游戏自身的旋转/翻转操作调整方向，箭头和端口随原生形状变换一起变化。

容器必须是玩家有效拥有的真实箱子、背包等。只读其直接库存，不递归暴露内部背包物品；不创造虚拟仓库。先放入一件普通测试物品。

线缆支持自动 connected texture：按四个端口的实际接触显示 16 种连接外观，在部件放置、移除或旋转后合并到下一次更新刷新。十字相接会连通；本轮采用自动贴图方案，没有引入手动切换模式。**贴图表示物理接触，不保证频道在线。**

占格来自真实 modifiedShape 的 GetLocal/ForwardTransform，不用屏幕坐标猜测旋转。端点不充当线缆，不通过终端或总线桥接独立网络；接触两个不同传输分量的终端保持离线。

## 只读复测顺序

1. 生成一次套件，确认 main/nested 数量与可见部件一致，确认核心占九格。
2. 按上图只放一个核心，双击终端，应显示 Online；默认核心容量 32、每段管线容量 8，终端和总线各占 1。
3. 将装有一件普通物品的容器放在总线箭头面，刷新，确认出现该物品。其他侧面的容器不应出现。
4. 移开箭头面容器，其他侧面保留容器，刷新，应失去接入。转动总线并重新连接其背面，验证新的箭头面。
5. 检查放置、移除、旋转线缆后连接贴图改变；断开网络再刷新，物品应消失，重连后恢复。
6. 同类但不同状态的两个物品应保持独立实例。短 ID 仅属于本会话，不是游戏持久 ID。

无核心、多核心冲突、频道不足都会离线。关闭频道限制不解除多核心冲突。总线的“设备 Online”与“本终端可访问”分别显示，其他网络的在线总线不会泄漏物品。

终端按需读取，**翻页复用本次观测**：物品每页 30、总线每页 8、主库存候选每页 20。刷新按钮重新观测；不承诺窗口自动实时同步。每次实际取放均独立重读，源库存或目标容器与页面观测不一致时拒绝操作，旧页面不能授权写入。F9 > Special > AE: Diagnose 或“只读诊断”可查看原生坐标、旋转/翻转、连接和容器观测。

## 实验取放（默认关闭）

只在前述只读检查通过后，才手动开启“实验取放（仅测试档；整实例、不堆叠）”。取出目标为主库存；存入先选择当前总线页的在线目标，再选主库存物品。AE 设备和已接入容器不出现在存入候选中。

只请求精确对象的整实例移动，不主动拆分、堆叠或自动嵌套。容量不足、拒收、原生预检选择堆叠/嵌套位置时拒绝；不强行绕过原生规则。原生回调仍可能改变结果。

**不是原子事务。** 移动前重读并检查方向、连接、频道、实例、有效拥有和接收规则，经 SlotMarker.TryAcceptOnce 后再检查身份、数量和归属。未知或部分结果会锁定本会话写入；不自动重试、回滚、销毁或补造已有物品。请停止测试并保留错误。

## 反馈与结束测试

反馈包名/源码后缀、具体按键与步骤、完整主物品栏布局、终端状态及只读诊断。F8 若仍被字体警告刷屏，可在 %USERPROFILE%\AppData\LocalLow 中找到本游戏最近更新的 Player.log，提供相关日志；无需游戏 DLL 或存档，可遮盖本地用户名/路径。

保存/载入、停用/卸载、原生取放回调和其他模组兼容仍未验证。最稳妥的测试结束方式是弃用此独立测试档。若要保留，先移除全部 AE 部件再按游戏流程保存，之后停用模组并重启。接入物品仍由真实容器保存，不属于总线的虚拟存储。
