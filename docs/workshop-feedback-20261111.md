# 工坊断网反馈调查（0.15.2-alpha）

此页保留 0.15.2 的调查和验收记录。其“设备不转发网络”的限制已在 0.15.3 移除，当前规则见下方更新及功能规格。

反馈来源：[Yakumo_inori，2026-11-08](https://steamcommunity.com/sharedfiles/filedetails/?id=3834652519#comment_573805817327052177)。玩家描述终端、驱动器和接口贴着控制器时，增加线缆会掉线，并指出这些设备不能转发网络。2026-11-11 重新核对页面，仍有三条评论，没有新的补充。

## 原因与修复

`PhysicalNetworkProjection.Build` 先为核心和线缆计算传输分量，再把末端设备接到一个分量。旧代码把所有不同分量都视为竞争网络：设备一侧直接接核心，另一侧碰到未接入核心的线段时，也会被标为歧义并完全断开。最终 `NetworkEvaluation` 将其报告为 `NoCore`。这属于组网逻辑错误，与 Rev13 拖拽 API 无关。

0.15.2 以是否含有核心区分接触分量。设备接触唯一含核心的分量时选择该分量，忽略无核心线段；仍只保留一个逻辑连接。两个独立含核心分量继续视为歧义，已经含多个核心的冲突分量也不会被忽略。选择结果不依赖物品观察顺序，不增加每帧扫描。

当时仅修复掉线，保留了原型中的叶子设备限制：终端、驱动器和接口不给另一侧转发网络。该限制并非 AE2 的完整方块设备规则，也没有发现必须保留的游戏 API、存档或性能约束；0.15.3 已修正这一设计。

## 复现与验收

- 模型回归覆盖八类叶子设备、直接接核心与经线缆接核心、多个悬空分支、观察顺序、隔离及多核心冲突。新增十个测试在旧实现上均失败；修复后完整 125 个模型用例通过。原驱动器和能源接收器测试同时核验悬空线段不被桥接、第二核心仍触发歧义。
- 独立实机宿主使用正式游戏的真实物品、占格和原生库存搬运，不复制组网算法。对终端、驱动器、物品接口、流体接口依次执行直接贴核心、加悬空线段、线段接回核心、接第二个独立核心、移除第二核心，共20个布局观察点。
- 在未修改的 0.15.1 正式包（提交 `20e64d6`）上，四类设备均复现相同问题：直接贴核心为 Online，加悬空线段后为 NoCore，线段接回核心后恢复；移除第二核心但保留悬空线段时再次错误离线。20个观察点中这8项失败，其他12项符合预期。
- 随后保存并通过原生场景重载同一新建测试槽，核对物品 ID、设备连接和远端隔离。最终结果及截图记录在 `artifacts/runtime-tests/*-workshop-topology-*`，以各报告的 `productCommit` 和 `topology-observations.json` 为准。
- 测试仅使用新建独立槽，每轮运行前备份存档。此前玩家存档不作为夹具。不据此声称完成硬件鼠标或所有其他模组交互验收。

另外两条工坊评论分别是元件获取方式提问和简短正面评价，没有另一个具体故障描述。原文尚未附截图或存档；本次复现对应“设备贴核心后再加未接入核心的线段”，不能推定覆盖玩家未提供的其他布局。未发送工坊回复或公开发布。

## 0.15.3 设备转发修复（2026-11-12）

历史根提交 `9105a90` 将功能设备当作只有一个连接的末端；`ee1e9d2` 移除频道数量限制时沿用了此规则。[AE2 官方连接说明](https://guide.appliedenergistics.org/1.21.1/ae2-mechanics/me-network-connections/)允许完整方块设备传网。现将功能设备身份与传输能力分开：终端、驱动器、两类接口和能源接收器保留所有合法接触并参与路径搜索；三类安装总线继续只有宿主连接，且占用面隔断外部接触。

设备串联及环路可以组网，连接两个核心会使整个连通网络报告冲突。设备功能、库存目录和耗电仍各计算一次；继续使用每网一次共享搜索和共享路径前缀，不修改原生库存或存档格式。

新增八个转发回归在 0.15.2 代码上全部失败，修改后完整 136 个模型用例通过，覆盖随机图独立搜索对照和五千设备长链。独立实机宿主扩展为五类设备、三类总线朝向、无缆串联、备用路径、断网旧窗口拒写、原生存入和保存重载；执行结果以新包对应的 `runtime-validation.json` 为准。前述 0.15.2 的 20 个布局观察点只证明旧行为，不能作为新转发规则的验收记录。
