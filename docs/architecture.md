# 架构边界

## 目标与阶段

玩法方向是在主物品栏放置核心、连接件和接口，发现可连接的真实容器。首版优先统一索引和安全取放；效率、扩展性与兼容性高于提前加入完整功能。当前有逻辑拓扑、频道、内存原型，以及用真实引用编译的游戏适配测试版。自动合成、物流调度、自有持久化格式仍未实现；基础交互版本已由用户确认可用，0.2 新功能仍待真实运行。

## 依赖方向

`GameAdapter -> Core <- Tests`。Core 不引用 Unity、Harmony、Steam、游戏程序集、文件系统或数据库。没有 `IGameInventory` 等臆造的游戏契约；真实 API 未核验前不固定坐标、旋转、事件或搬运方法签名。

Core 目前包含：

- `ItemInstance`：模型实例 `Guid`、物品类型字符串、不可变的不透明 `StateTag`。Guid 不是已证实的游戏持久 ID；StateTag 不是游戏状态的完整序列化，也不是可堆叠判据。
- `ContainerSnapshot`：复制输入集合的不可变观测。没有坐标、格子或容量模型。
- `SnapshotIndex`：一次性只读聚合，按实例 ID 查询；重复实例或重复容器身份直接拒绝，避免静默覆盖。构建 O(n)、查询平均 O(1)、空间 O(n)，尚无基准测试或增量更新保证。它是观测缓存，不能代替真实容器成为物品权威来源。
- `NetworkTopology`：核心、管线、存储总线、终端的不可变显式连接；不包含实际主物品栏坐标。`NetworkEvaluation` 在核心和路径管线上分配频道，`TerminalCatalog` 只聚合同一核心下在线总线的最新容器快照。规则与限制见 [网络原型](network-prototype.md)。
- `PhysicalNetworkProjection`：把适配器提供的原生占格接触观测映射为逻辑网络；同一叶子接触两个不同传输连通分量时离线，避免靠终端或总线桥接。纯算法测试覆盖输入顺序、多面接触和网络隔离。

将来在真实变更信号核验后，再决定失效、重扫与增量索引策略；取放前必须重新验证容器、实例归属、状态和目标可接收条件。不要仅凭旧快照执行写入。

## 测试替身与搬运风险

`Tests/Simulation`（实际目录 `tests/DeepSpaceAE.Tests/Simulation`）中的容器只用字典保存实例，容量按实例数量计算，不模拟主库存格子、旋转、堆叠、嵌套、重量或线程。顺序搬运器只用于构造可失败的模型试验，没有生产代码调用入口。

模拟器在已知失败点返回结果；成功项目保留，失败项目在源容器。批次没有回滚。请求缓存仅用于同一进程/会话内的模型重放；相同请求 ID 不能换源、目标或有序实例列表。注入失败在单项写入之前，不覆盖真实游戏“已经写入后抛异常”“回调重入”“超时结果未知”等危险状态。未知结果不能盲目重试。

开发终端复用 Tests 中的容器，不增加第四个运行时项目。Core 负责只读拓扑与索引；终端宿主的取放仅操作测试字典，每次先刷新连通性、频道与容器观测。`take` 精确选择实例，`put` 指定在线总线，不做自动堆叠或跨容器批次。原有请求重放测试属于单独的模拟会话；CLI 没有持久化请求 ID 协议，不提供跨重启重试保证。

**不承诺跨容器原子事务。** 将来遇到部分完成、事件递归、失效对象或存档中断，应记录逐项已知/未知结果，重新读取真实状态并停止危险操作；具体恢复策略必须经真实 API 试验后设计。禁止把模型假设升级为游戏安全保证。

## GameAdapter（0.3）

终端现在是无物品所有权的真实原生网格投影；控制器和总线采用原生机器样式，并借用既有真实槽的渲染。幽灵格复制类型/类别，不移动原物。存档数据图顺序不因新窗口重排而改变。输入接入原生拖拽，只在释放时执行一次新鲜核验的移动，虚拟库存拒绝原生接收。详见 [原生 UI 迁移](native-ui.md)。

ModEntry 注册四种供电节点、容量卡、标签卡、扳手和原生拾荒权重。GameSession/PartStorage 使用用户提供的真实 API：主库存统一为 EmporiumEntry.Instance.invElement，真实原生子库存承载电池与升级，GameItem.state 承载配置和按天结算。双击补丁只作用于本模组组件，锁定交换补丁只作用于 AE 子库存。其他物品的激活和搬运保持原生规则。

正式终端覆盖同一核心下的全部可访问直接容器，先编译总线权限，再逐实例构建带标签的目录。窗口翻页复用搜索结果，库存/数量事件批量失效；每次写入重新观测连通性、供电、来源和目标。不能用页面缓存授权移动。只移动整个实际实例，不克隆、拆分、强制堆叠；未知原生后置条件锁定操作，不自动补偿。

供电按最高日预算锁定真实电池，睡眠时先标记扣电开始，再调用原生供电函数并核对结果，次日日计数推进后解锁。原生存档保存子图、状态、uniqueId；加载恢复锁，禁止把中断的 DebitStarted 当作可重放请求。完整原生契约、复杂度、保留边界见 [0.2 功能](storage-features.md)。

## 分发边界

IsPackable=false；游戏 ZIP 使用 scripts/package-game.py 逐文件白名单：两个自有 DLL、43 张授权 PNG、manifest、安装验收说明、素材署名/来源与构建记录。检查干净提交、二进制内嵌提交、PNG 头、逐文件哈希和 ZIP CRC。游戏/Unity/Harmony/Steam DLL、测试宿主、存档和凭据不得进入 Git 或安装包。源素材是公开 AE2 代码库的资产子集，许可 CC BY-NC-SA 3.0，随包保留署名，不与早期原创 CC0 占位 SVG 混淆。

源码修复按用户授权直接推送；附件交付需真实上传工具或用户指定渠道，不把 /workspace 或虚构 Library ID 当成下载链接。不操作本地电脑、不登录 Steam、不安装 Unity/Wine。

0.3.1 增加真实 PE 元数据门禁（Tests CLI --audit-game），不执行游戏代码；禁止给抽象方法打补丁。自有界面文案通过官方 en/zh CSV 读取，静态目录只保存 ASCII 键。打包另含这两份 CSV、加载诊断说明与独立日志提取器；其余 DLL/素材白名单不变。详见 docs/load-troubleshooting.md。
