# 架构

Core以netstandard2.1实现拓扑、频道和容量等纯逻辑，不引用游戏对象。GameAdapter绑定游戏程序集，将真实物品、库存及原生交互接入网络。Tests中的模型容器与RuntimeTests中的游戏夹具不随模组发布。

## 权威数据与网络

屏幕主库存为 `EmporiumEntry.Instance.invElement`，统一通过GameSession访问。不能用独立的 `PlayerStore.GetStoreInventory()` 替代。
主栏真实占格、旋转和翻转构成空间索引；按接触关系建立传输分量和叶子设备，评估单核心及频道规则。UI缓存只用于展示，不授权写入。

线缆含四面真实总线子库存；安装面阻断外部连接。驱动器含十个真实盘位及四个容量卡位；硬盘保存真实物品但只按面积计容。抽屉保存同种物品的真实实例，卡片不作为网络目录内容。

## 原生交互

终端是独立纯UI镜像，命中指向真实顶端物品，不借走源渲染、不复制GameItem、不拥有库存。
实际搬运经一次新鲜网络/权限检查和原生找槽，接受 `SlotMarker.TryAcceptOnce` 的数量返回值。
原生拒收或异常只结束当前操作，不追加数量/归属收据或永久故障锁；批量操作逐项执行，不承诺跨容器原子事务。

物品接口将非拥有落点重定向至真实网络目标。流体接口拥有20升原生WaterHelper缓冲，只通过原生TransferLiquid转移。
输入/输出总线读取真实机器UI树中的MachineryPanel.role和直属库存，分别使用output/input槽；不猜库存索引。

## 供电与生命周期

默认免电，保留拓扑、频道、筛选和原生锁。实验耗电启用后按当日峰值预留最少电源组合，睡眠时扣电；原生bool与付款事件决定结算。
已成功结算不重放；失败记Shortfall并释放失败及未执行份额。库存、配置、日期及设置事件驱动合并刷新，关闭窗口、停用和加载时解除旧订阅。

## 分发

`scripts/package-game.py`只收录显式白名单中的两个自有DLL、119张PNG、两份本地化、清单、玩家指南、源码及素材许可和来源说明。
游戏/Unity/Harmony DLL、测试宿主、存档、凭据、本地配置和开发记录不分发。Release禁用调试符号，并将编译路径映射至固定虚拟根。
