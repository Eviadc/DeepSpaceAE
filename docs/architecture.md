# 架构边界

## 目标与阶段

玩法方向是在主物品栏放置核心、连接件和接口，发现可连接的真实容器。首版优先统一索引和安全取放；效率、扩展性与兼容性高于提前加入完整功能。当前有逻辑拓扑、频道、内存原型，以及用真实引用编译的游戏适配测试版。自动合成、物流调度、自有持久化格式仍未实现；本次交互、方向和连接贴图修订尚未真实运行。

## 依赖方向

`GameAdapter -> Core <- Tests`。Core 不引用 Unity、Harmony、Steam、游戏程序集、文件系统或数据库。没有 `IGameInventory` 等臆造的游戏契约；真实 API 未核验前不固定坐标、旋转、事件或搬运方法签名。

Core 目前包含：

- `ItemInstance`：模型实例 `Guid`、物品类型字符串、不可变的不透明 `StateTag`。Guid 不是已证实的游戏持久 ID；StateTag 不是游戏状态的完整序列化，也不是可堆叠判据。
- `ContainerSnapshot`：复制输入集合的不可变观测。没有坐标、格子或容量模型。
- `SnapshotIndex`：一次性只读聚合，按实例 ID 查询；重复实例或重复容器身份直接拒绝，避免静默覆盖。构建 O(n)、查询平均 O(1)、空间 O(n)，尚无基准测试或增量更新保证。它是观测缓存，不能代替真实容器成为物品权威来源。
- `NetworkTopology`：核心、管线、存储总线、终端的不可变显式连接；不包含实际主物品栏坐标。`NetworkEvaluation` 在核心和路径管线上分配频道，`TerminalCatalog` 只聚合同一核心下在线总线的最新容器快照。规则与限制见 [网络原型](network-prototype.md)。
- `PhysicalNetworkProjection`：把适配器提供的原生占格接触观测映射为逻辑网络；同一叶子接触两个不同传输连通分量时离线，避免靠终端或总线桥接。纯算法测试覆盖输入顺序、多面接触和网络隔离。

将来在真实变更信号核验后，再决定失效、重扫与增量索引策略；取放前必须重新验证容器、实例归属、状态和目标可接收条件。不要仅凭旧快照执行写入。

## 测试替身与搬运风险

`Tests/Simulation`（实际目录 `tests/DeepSpaceAE.Tests/Simulation`）中的容器只用字典保存实例，容量按实例数量计算，不模拟主库存格子、旋转、堆叠、嵌套、重量或线程。顺序搬运器只用于构造可失败的模型试验，没有生产代码调用入口。

模拟器在已知失败点返回结果；成功项目保留，失败项目在源容器。批次没有回滚。请求缓存仅用于同一进程/会话内的模型重放；相同请求 ID 不能换源、目标或有序实例列表。注入失败在单项写入之前，不覆盖真实游戏“已经写入后抛异常”“回调重入”“超时结果未知”等危险状态。未知结果不能盲目重试。

开发终端复用 Tests 中的容器，不增加第四个运行时项目。Core 负责只读拓扑与索引；终端宿主的取放仅操作测试字典，每次先刷新连通性、频道与容器观测。`take` 精确选择实例，`put` 指定在线总线，不做自动堆叠或跨容器批次。原有请求重放测试属于单独的模拟会话；CLI 没有持久化请求 ID 协议，不提供跨重启重试保证。

**不承诺跨容器原子事务。** 将来遇到部分完成、事件递归、失效对象或存档中断，应记录逐项已知/未知结果，重新读取真实状态并停止危险操作；具体恢复策略必须经真实 API 试验后设计。禁止把模型假设升级为游戏安全保证。

## GameAdapter

`ModEntry` 实现真实 `IMod`，通过已核验的物品目录钩子注册四种部件及 F9 测试入口；`GameSession` 负责原生库存观测、会话身份、接入选择和自定义 UI。它不引用测试容器或复制游戏类型。typed Harmony 补丁只为自有部件提供双击入口、阻止原生单击窗口，并以常数成本通知自有部件位姿变化；不修改其他物品交互。

主库存统一由 `GameSession.MainInventory()` 读取 `EmporiumEntry.Instance.invElement`：该实例在真实 100-REV3 程序集中被挂到 `invWindow`，并注册 MainInvArea 增删回调。原包错误使用 `PlayerStore.GetStoreInventory()`，后者返回另一份未挂到主库存窗口的独立库存，详见 [本地反馈与根因](game-runtime-feedback.md)。诊断可只读比较两份库存，但后者不再用于网络或搬运目标。InventoryLayout 一次枚举原生 GetLocal/ForwardTransform 占格并建立格子索引，替代反复调用 IsAdjacent 与两两扫描；总线只在箭头面查容器，背面接线。容器仅枚举直接子库存。只读与取放均按需重读；不替换原生库存回调，不把旧窗口当作写入授权。频道和总线选择仅在内存会话中保留，加载存档时清除写入许可及接入选择，弱引用 Guid 不作为持久身份。

实验取放默认关闭。开启后仅请求原生入口移动整实例，拒绝堆叠、拆分、自动嵌套位置，前后检查身份、数量与归属，重入时拒绝第二次操作。异常或未知结果锁定本会话写入，不回滚、重试、销毁或补造已有物品。原生入口内部可能先逐出再接收，因此不能据静态检查保证原子性或所有回调下的安全。

真实程序集哈希和静态 API 证据见 [核验清单](api-verification.md)。游戏加载、回调、UI、存档及跨模组行为仍等待用户在独立测试档运行。外部路径注入合法引用，`Private=false`，不得提交或重新分发。

## 分发边界

`IsPackable=false` 继续禁止 NuGet 打包。游戏 ZIP 由 `scripts/package-game.py` 使用逐文件白名单生成：两份自有 DLL、manifest、20 张原创 PNG、测试说明与构建记录。打包检查干净源码提交、二进制内嵌提交、清单 DLL 列表、PNG 头、ZIP CRC 及逐文件 SHA-256；拒绝递归打包 bin 或 Managed。游戏/Unity/Harmony/Steam DLL、测试依赖和存档均不进入安装包。不操作本地电脑；源码修复按用户授权推送，安装包另行交付，不自动发布工坊。

OccupiedGrid 保存适配层提供的显式格子，提供查格、四端口掩码与重叠拒绝，不是模拟游戏库存。频道算法复用剩余容量可达树，频道关闭时一次遍历汇总需求。路线前缀共享、仅显式访问 Route 时展开。分页复用只读观测，写入仍强制重新观测；纹理缓存只影响外观。完整成本和局限见 [性能记录](performance.md)。
