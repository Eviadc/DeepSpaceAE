# 复杂度与连接贴图核验

0.2 新功能复杂度补充见 [存储与供电](storage-features.md)。0.3 终端已经改为按真实占格分页的网络投影，没有主栏候选面板；布局和 0.3.2 UI 修订见 [原生 UI](native-ui.md)。下面的测量仅记录 37f61bf 的 Core 算法。当前明暗刷新读取真实主栏占格，成本为 O(N+S)，不再只读取自有部件。

本轮目标是消除重复全量搜索，明确上界并提供可重复测量；没有把“极低复杂度”解释成所有操作都是 O(1)。完整观测和输出至少需要读取对应输入，原生游戏函数和 Unity UI 的耗时也不能由 Core 模型测试保证。

## 已确认的真实 API

100-REV3 用户引用中，ItemDefaultActivateHandler.OnEventPress 会在 activateDefault 为真时抢占输入并激活。四类自有部件均关闭这个入口和原生单击激活，限定到自有物品的 typed Harmony 补丁从 ItemMouseDoubleClickHandler.DoubleClickAction 打开窗口，并阻止其 ClickAction 单击分支打开 AE 部件的原生查看窗口。不更改全局单击设置或其他物品行为。

原生 GridShape.GetLocal/ForwardTransform 给出占格和旋转/翻转映射。接入面取自总线本地东侧，网络面为反方向；通过变换后的唯一相邻格查询容器，不以包围框或屏幕位置猜方向。

GameItem.SetSpriteQuick 和 GameItemElement.ApplyAnimationFrame 均可动态换自有精灵。实际实现从 OnModAssetsLoaded 缓存本模组 Sprites 字典，调用 ApplyAnimationFrame 更新真实和拖拽预览图，并更新 spritePath；每次变化不再遍历模组列表。16 种贴图由自有脚本生成，证明静态路径可行，实际显示尚未在游戏运行。

线缆刷新订阅主库存的 add/remove End 回调；ValidateShapeState 后置补丁只检查自有部件的位姿是否变化。连续变化合并到 LetterboxManager.RunNextUpdate 的一次回调。只替换发生变化的精灵，不分配运行时纹理、不重建占格、不每帧轮询网络。停用和载入时解除订阅、使旧回调失效。

## 成本及边界

记 N 为主库存直接物品数，S 为它们原生占格局部矩形的总扫描格数（包含空洞），A 为实际占用格数，V/E 为网络节点/边数，D 为终端/总线数，M 为本终端可访问容器的直接物品实例数，C 为核心频道上限（默认 32），L 为路径长度。

| 操作 | 时间与空间 |
| --- | --- |
| 一次新鲜占格观测 | 期望 O(N+S) 时间、O(A+N) 空间；哈希查格期望 O(1)，重叠观测拒绝 |
| 一个总线查容器 | 观测建好后一次查格，期望 O(1)；容器内容结构仅对实际箭头面候选按需遍历 |
| 一个线缆连接掩码 | 恰好四次查格，期望 O(1)，用游戏原生变换解释本地方向 |
| 物理拓扑投影 | 分量与端点处理 O(V+E)，不再逐对比较 V²，也不再为每个端点重扫全部边；公开拓扑的稳定排序另计 O(V log V+E log E) 上界 |
| 频道关闭 | 一次 BFS + 子树需求汇总 O(V+E+D)，端点稳定排序 O(D log D)；共享不可变路径前缀，默认不为每台设备展开整条路线 |
| 频道开启 | O(K(V+E)+C·L+D log D)，K 为搜索轮数；只在成功路由使管线饱和后失效搜索树，失败设备复用结果，单核心默认 K≤32。可配置 C 增大时上界也随之增大 |
| 显式读取完整路线 | 首次 O(L) 构造并缓存列表；读取全部路线需承担真实输出总长度，不能宣称仍为 O(V) |
| 物品索引 | 期望 O(M) 构建、期望 O(1) 按实例查询；仅枚举本终端在线网络的容器，重复总线不重复扫描同一容器 |
| 窗口翻页 | 复用观测及布局，只重绘当前占格页；常规页面 18×12，超大单件扩页。成本与当前页占格有关，不重新观测全网或排序全部物品 |
| 实际取放 | 保留前后新鲜观测，成本受 S、V/E、M 及原生接收/回调规则影响；源库存和目标容器必须与页面观测一致，没有为了速度使用旧页面授权写入 |
| 连接贴图变化 | 每批事件 O(N+9V) 构建自有部件占格，逐线缆四次查询；静止时无本模组网络扫描。未假装做到任意游戏变更下的 O(1) 增量更新 |

容器内部结构遍历、有效拥有和原生搬运自身的成本没有隐藏在 O(1) 查格中。当前目录按已订阅的库存/数量、网络及配置事件合并重读，打开窗口和执行移动时也重新观测；没有手动刷新按钮，未知全局变更事件的覆盖仍待实测。纹理事件缓存只影响外观，不作为物品权威来源。字典复杂度是期望值，不是对恶意哈希碰撞的严格最坏界。

0.3.2 新增交互成本：按格命中期望 O(1)，选中高亮只遍历前后两件物品的占格；借用槽尺寸刷新限于该槽的原生 Validate。输入/下拉装饰的公开属性反射只在创建控件时执行，成本与该控件子组件数有关。核心动画复用原版管理器：每次 Tick 遍历登记的活动核心，只有帧号变化才换图，非逐帧扫描网络，也不为动画分配新纹理。离线/拆离/停用移除登记；不将原版动画管理器的内部循环或原生库存函数声称为 O(1)。

## 可重复验证

    bash scripts/verify.sh
    python3 scripts/generate-game-assets.py --check
    bash scripts/demo.sh --benchmark

模型回归包括 320 组随机图配置与独立的逐设备 BFS 基线比对，验证状态、路径和频道用量不变；另有长链共享搜索、饱和切断不重复搜索、四种方向、镜像/旋转输入、全部 16 连接掩码、PNG 端口边缘和 3×3 核心素材检查。

性能探针排除一次预热，每组采样五次，输出时间中位数、当前线程分配字节数和实际搜索访问次数。范围仅为现代 .NET 上的 Core 模型，不是 Unity/Mono、游戏 FPS 或其他模组兼容基准。最终执行结果随本次源码的验证记录交付，不能用旧数据证明新代码。

## 0.9.1 审查与 Windows 模型复核

供电每次 ReadBoard/夜间批次构造一次临时 PowerSnapshot，按核心索引旧预留，恢复锁限于该核心和相关接收器，不再每核心重复遍历所有电源宿主。候选、既有份额和已选份额用字典/集合连接；PowerSelection 排序 O(P log P)，前缀和与保留数选择 O(P)，避免 O(P²) 的数组重建。实际有效拥有、供电判断和原生锁/回调开销另计；索引不能替代扣费前实时原生核验。自动化路由也不再按每个设备 ID 执行一次线性 Single 搜索。

2026-11-01 Windows，SDK 10.0.403，本次 Core 探针五次中位数：20,001 节点、10,000 物品，开启频道时拓扑/评估 62.200 ms、2 次共享搜索/10,002 传输节点访问；关闭频道时 64.159 ms、1 次/10,001 访问。两者空间建索引/掩码 1.257 ms，物品索引 0.404 ms，可见布局构建 4.658 ms。输出为忽略文件 artifacts/audit-benchmark.json。这仅证明本机现代 .NET 模型的本次测量，没有测量 Unity 帧率、原生移动或跨模组回调成本。
