# DeepSpaceAE 功能规格 · 0.6.0-alpha

维护基线：100-Rev6 / Steam Build 26337366，Windows x64。本文描述当前代码的预期行为；不把编译、模型或静态审计当作游戏运行结论。具体操作和验收记录见 [功能用例](functional-cases.md)，版本升级入口见 [维护指南](version-maintenance.md)。自动合成尚未实现。

## 物品与网络

| 物品 ID（统一前缀 deepspaceae.） | 名称 | 主栏占格 | 频道 | 每日网络成本 kJ |
| --- | --- | --- | --- | --- |
| core | 核心 | 3×3 | 提供 32 | 2 |
| pipeline | 线缆 | 1×1 | 通过容量 8 | 0 |
| item_storage_bus | 存储总线升级 | 未安装时 1×1 | 安装后 1 | 1 |
| terminal | 终端 | 1×1 | 1 | 1 |
| disk_drive | 硬盘驱动器 | 2×2 | 1，与盘数无关 | 1 |
| disk_small / disk_large | 小 / 大硬盘 | 均 1×2 | 无 | 随驱动器计算 |
| capacity_upgrade / tag_upgrade | 容量卡 / 类别卡 | 1×1 | 无 | 随总线计算 |
| wrench | 扳手 | 1×1 | 无 | 无 |

部件必须直接位于玩家拥有的屏幕主库存 `EmporiumEntry.Instance.invElement`。根据真实占格接触、旋转和翻转建立拓扑；同一连通网络只有一个核心，双核心冲突时离线。总线、终端和驱动器都是叶子，不用它们桥接两个独立传输分量；同时接触两个分量会离线。频道不足的设备不可访问。组件单击保留原生操作，双击打开模组界面；线缆双击只命中对应总线部位，中心无独立 UI。

核心使用原生机器面板、电池槽、能量条、设备数量和频道统计。有电联网时播放 12 帧灯光；线缆使用 16 种自动连接纹理；离线/禁用停止动画。连接与刷新由原生变更事件合并触发，没有每帧全量扫描。

## 线缆和总线

每根线缆有四个本地方向的总线升级位，升级真实存在于线缆子库存中。拖入总线时优先未连接且未安装的面，否则选择一个已连接空面并切断该面传输。装满四面会使线缆不能向外连接。移动/旋转/翻转整根线缆时，总线随之变化。总线朝外的一面识别相邻真实容器，所在面不再传输线缆网络。

线缆整格可点击。双击可见总线部位打开对应配置；扳手对准该部位卸回主栏，保留升级卡和设置。主栏没有可用位置时拒绝。旧独立摆放总线不自动迁移，按用户决定手动拆换。

每条总线支持：优先级、读写/仅存入/仅取出、物品类型或类别过滤、包含/排除、是否对提取应用筛选。同一真实容器被多条总线观察时只列一次物品，提取权限取允许总线的并集；插入按优先级降序、稳定身份顺序逐个尝试可用目标。

九列幽灵格默认 18 格，每张容量卡增加 9 格，最多五张，共 63 格；不使用滚动条，直接扩展行数。类别卡占一个升级槽，每条总线最多一张，因此最多四张容量卡、54 格。物品拖入幽灵格只记录类型/类别，真实物品不离开源库存；点击清除。容量减少后保留超出活动格范围的设置但不生效，恢复卡片可重新启用。类别选项只来自拖入物品自身的原版类别，不枚举全游戏物品。用扳手逐张拆卡。

## 终端交互与读写

终端保留原版库存背景和连续滚动条，无分页。使用独立、非拥有的纯 UI 镜像展示真实多格形状、旋转、翻转、数量及动态图层；镜像命中指向原物品。源容器可以同时显示和操作同一物品，终端不借走原渲染、不复制 GameItem、不改变物品归属、不将镜像写进保存图。

可按名称/ID 多词搜索、`#类别`、类别下拉筛选，按原顺序/名称/数量排序。数量排序以当前筛选结果中同 ID 总量排序、同类连续，独立实例保留；同 ID 的电池电量等状态不会被合并。滚动只生成可见部分的镜像。目录、配置、数量、网络变化自动刷新，拖拽期间保留 dirty，结束后合并刷新；没有手动刷新按钮。

左键双击、右键菜单和单件拖拽复用原版处理，命中同一真实物品；从空白处框选可见物品，蓝色显示选中占格，沿用原版群组拖拽状态和取消。群组预览用镜像位置，不挪源渲染。滚动、过滤、重建清理旧框选。向终端拖入单件或多件时高亮整个存入区域，不暗示存入某个投影格。

实际写入前重新观测网络、电力、权限、所有权、来源和目标原生槽。终端搬运整实例，不拆分、不自动堆叠，也不承诺批量原子性；逐项处理失败前已成功的项保留成功结果。满容器、断线、拒收或已知预检失败不动来源。原生调用进入后若结果不确定，锁定后续写入、保留不确定孤立实例、不自动重试、回滚或销毁。其他模组依赖原场景节点/保存图的特殊菜单与行为仍须单独实测。

## 驱动器和硬盘

驱动器直接接线缆，不需要总线；占一个频道和 1 kJ 网络成本。双击打开六个原生机器槽（3 列×2 行），使用原版 DNA 盘槽风格，仅接受本模组小/大硬盘，每槽一盘。各槽显示已用/容量，空驱动器可联网但没有可写介质。硬盘没有直接内容窗口，安装后通过终端访问。

小盘 64 格、大盘 256 格。每个真实物品实例以当前 `modifiedShape` 中值为 1 的格子数收费；五格异形物品占五格，旋转不改变占用，没有几何排布/碎片限制。堆叠实例按可见形状面积计，不乘数量；不通过终端拆分或堆叠。各盘独立计容，单件不跨盘拆放；按六槽顺序选择能容纳整件的盘。驱动器与总线共同路由，驱动器默认优先级 0、读写、无过滤。

存储介质使用真实原生库存/物品保存图。插入/取出驱动器的硬盘仍携带其内容；离线/拆盘立即从终端索引移除，内容不销毁。禁止盘/驱动器及含它们的容器存入硬盘，防止递归存储。原版所有权、移动锁和物品特殊准入规则继续检查。进入硬盘数据的原生 unchecked swap 被阻止，避免绕过容量；常规取放走终端的原生预检和移动路径。

以后容量缩小或存档出现超容量时，加载保留全部真实实例，禁止新增超额数据，不自动丢弃物品。原生在库物品形状/状态变化可能使占用增长，必须可提取恢复；是否存在带副作用的特殊物品仍需游戏验收。

## 供电和夜间结算

每日观察到的整网成本最大值作为当天预算：核心/线缆/总线/终端/驱动器分别 2/0/1/1/1 kJ。移除设备不会降低当天峰值。成本包括所属传输分量内设备，即使频道耗尽；孤立核心最低 2 kJ。重新加载不清空峰值或重复扣电。UI 区分当前网络成本与当日峰值。

普通电池插入时必须足以覆盖峰值，成功后锁定；夜间先持久化 DebitStarted，再调用原生扣电并核对结果，只扣一次。次日已结算电池可取出；重新供电会预留新日预算。若峰值增长超过当前电量，当日网络立即断电、取消电池锁定；同一电池不能清除当天 Shortfall，需换入另一块足量电池。依用户决定，普通电池不足且睡觉时仍未更换，未结算峰值次日清零，不追缴。超科技电池保留原生输出限制/无限能量语义。

原版 `current_converter`（电流转换器）可放进同一核心槽。开启且无停电事件时视作电网供电，不要求其模拟电池电量。以原版电力服务 `CURRENT_CONVERTER_SERVICE` 收费：将核心当日峰值与转换器原版费率计入总账单，其他原版机器照常合并；不会额外调用白天扣现金的 Supply。已累计成本不因关掉转换器或锁槽而消失。

实际 `RunStats.OnServicePaid` 事件是付款凭据。夜间没有对应付款时，下一天该供电源保持锁定、AE 网络断电；重新启用电力服务并在下一次夜间真实付款后恢复。原版停电导致账单合法免收为 0 时，原生 0 元付款事件仍视作结算，停电期间仍无供电。现金扣除和是否允许负余额沿用原版规则。

确定未付款和扣费结果未知分开处理。存档中 DebitStarted 若没有已观测的未付款结论，不能自动重放电池扣费或电网收费。发生 Fault/未知结算保持锁定，保留日志供调查，不靠重新插拔清除。

## 生命周期、获取与分发

十种物品通过官方工厂注册；拾荒组注入候选掉落，禁用清理注册组。具体概率随原版拾荒组权重，不保证必掉。英文/中文 CSV 使用 ASCII 键，资源就绪后的工厂/钩子解析；静态初始化不请求本地化。

核心电池、线缆总线、总线升级的旧保存图顺序保留；驱动器与硬盘只有自身新增子图。加载恢复槽锁和本地化名称，关闭面板归还被借用的电池/升级/盘槽包装。卸载前必须取回盘内物品、电源、升级并清除全部模组物品。

Windows 构建→元数据审计→白名单打包→退出游戏后备份旧模组并部署。安装包只含两个自有 DLL、67 PNG、2 CSV、manifest、说明、日志提取脚本、来源/许可和构建记录。游戏引用、测试宿主、存档、凭据与缓存不分发。AE2 衍生图片 CC BY-NC-SA 3.0，原创离线 SVG 单独 CC0，不混用声明。

## 0.6 液体存储与原版操作

总线外侧面对启用 LIQUID_CONTAINER_TAG、具备正的 LIQUID_CONTAINER_CAPACITY 的原版液体容器时，即使没有物品子库存也识别其化学液体。终端顶部切换“物品 / 液体”；液体卡片使用真实来源容器的非拥有 UI 镜像，显示成分名称和 ml，悬停显示各成分微升级体积、比例、总容量以及原生温度（存在时）。空罐也显示，供原版倒入操作。没有生成虚构的液体 GameItem、没有挪源渲染或新增保存图。

按 Liquid.Liquids 的真实 CURRENT_PART_* 整数读取，1 ml = 1000 原生单位。成分签名以完整成分 ID 和最简整数比例构造，不按名称、颜色、纯度四舍五入合并。每个来源容器独立列一条，相同成分也不汇总，以保留温度、过滤器、酒瓶状态等原生差异；同容器被多条总线观察只列一次。名称/成分名搜索、连续滚动和数量排序保留；数量使用真实液体体积，条目保持独立。不同容器卡片中的相同液体不是终端复制品。

原版交互为选中源容器后点击目标容器：可从终端选择联网容器向普通容器倒出，或从普通容器选择后点击终端卡片倒入。原版空滴管向目标吸取，其他工具和酒瓶保留自身原生限制。是否混液、倒多少、比例舍入、过滤耗材、温度、水质、声音及副作用均由原版 GameItem.Target 和它的回调执行；本模组不手工改液体标签、不再次调用 TransferLiquid。原版允许的混合仍允许，“分别显示”不禁止玩家主动混合。

液体卡片使用固定展示区域，不支持物品式拖走/框选整个来源罐；需要搬罐时直接用源主栏。关闭终端或切换模式取消从该终端开始的原生选择，避免留下失效源。既有物品模式拖放不变。

原生倒液执行前重新核验当前终端拓扑、供电、所有权、容器仍被总线观察及访问方向。普通倒出检查源提取、目标存入；空滴管反转。多总线取允许规则并集。当前类型/类别过滤以联网容器的原生类型/类别作样本，不新增虚构“液体物品”或化学成分幽灵样本；仅存入的容器可作为目标，内容提示隐藏。异常原生调用保持终端写锁，不重试或回滚。

原生液体转移后合并刷新；来源成分数值、体积、温度或容量变化也能使观测失效，不能只比较“标签键是否存在”。液体仍由原容器的原生状态保存，断线/拆总线/关窗不销毁或迁移内容。

支持范围为当前游戏的化学液体容器模型；与其共用 LIQUID_CONTAINER_TAG 但只有旧式 LIQUID_CONTAINER_CURRENT/MAX 饮水计数的对象，不推断成分。未开放为原生液体容器的封装物品（例如特定酒瓶状态）不冒充空罐，需按原版先处理。
